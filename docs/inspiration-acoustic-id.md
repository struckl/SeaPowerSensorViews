# Acoustic ID (ACID) – what to take as inspiration

Looked at 2026-11-03: Workshop item 3825453562 "ACID - Acoustic ID" by KillerFox2S (needs Anchor Chain), description page and
the author's v1.1.0 announcement. No licence stated: ideas only, no code, no look copied. Its change notes were not readable (Steam
returned 429).

## What ACID does

- Passive sonar **identification game**: narrowband (frequency/tonal) display and broadband bearing displays with scrolling
  histories; a searchable reference library (class groups, country filter, signature previews); the player forms identification
  hypotheses and puts tentative labels on the map. "Manual sonar ID" (default) holds back the game's automatic sonar classification.
- Class "fingerprints" are generated by the mod (also for modded ships) and saved locally; recordings (tonal frequencies) can be
  saved and shipped with a mission as an intelligence clue (`<mission>.acousticid.tsv`).
- 1.1.0: active sonar analysis (echoes by bearing/range, relative scope, **measuring cursor**, **comparative depth gauge**); intercept
  analysis (bearing history, directional signals, spectrum); **selectable arrays** (hull, towed/VDS, dipping) that respect deployment
  and operating state; difficulty levels (Assisted / Standard / Expert / Custom).
- Opened with a sonar button or **F8** (rebindable); it lives in the game's window stack.

## Where Sensor Views stands next to it

- ACID is about *what is this contact* (classification by sound). Sensor Views is about *who holds which contact with which sensor*
  (detection picture across all sensors). Keep it that way: no tonal identification game, no library, no hiding the game's own
  classification. Players can run both.
- Possible clash: both add a sonar window and a bottom-bar sonar button; ACID defaults to F8 (Sensor Views moved off the F-keys, good).
  Name ours clearly ("Sonar picture" / "Sonar display") and test both mods together.

## Ideas worth taking (built our own way, game data only)

1. **Array selector that respects state** (sonar display): instead of `<` `>` cycling, a small selector Hull / Towed / VDS / Dipping
   showing deployed / stowed / off, and the waterfall says "array not deployed" instead of drawing nothing.
2. **Measuring cursor** (sonar waterfall done 2026-11-03, scope done too) (radar scope and sonar display): hover shows bearing and range (scope) or bearing and time ago (waterfall);
   drag from own ship for a range/bearing ruler.
3. **Comparative depth gauge** (done 2026-11-03, untested in game) (sonar depth strip): own depth, layer, seabed and the contact's *estimated* depth band where the track has
   one, so "above/below the layer" is visible at a glance.
4. **Bearing history per contact** (done 2026-11-03, untested in game) (board detail): the last minutes of bearings of a bearing-only track as a small strip, showing drift
   (the raw input of TMA), from track estimates only.
5. **Active sonar echoes** (done as the Echoes button, untested in game) on the scope page or the sonar display: active-sonar tracks as echo marks by bearing/range with fix age,
   separate from passive traces.
6. **Display levels** (later): a simple setting that hides detail (errors, wedges, ages) for a cleaner look, not a difficulty system.

Not taken: frequency spectrum / tonals (the game has no narrowband model; ACID invents fingerprints), recordings and mission packs,
manual ID.
