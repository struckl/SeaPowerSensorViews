# Sonar and acoustics – what a mod can read and call

Source: a code-reading sub-agent, 2026-10-28, on the decompiled **0.8.7** sources (`_gamerefs/decomp-0.8.7`). Paths relative to `Seapower\` unless noted. **Line numbers are 0.8.7;
the globe build (`_gamerefs/decomp-beta`) is shifted by roughly +30.** Spot-checked in both builds: `SonarContactMath.Evaluate(in SonarContactData)`, `Sonar.Subscribe(IObserver<Entity>)`,
`ObjectBaseParameters._sonarSystems`, `Environment.getLayerHeight`, `DM_Sensors._allowTMAFans`, `Sonar.RawPassiveSonarReadings`, `SensorInfoViewModel`. Everything else: re-check.

Verdict: the whole acoustic model is managed C# (not Burst), a public pure per-pair function, and the game itself already sweeps it in-mission to plot detection range.

## 1. Sonar types and listing
- `SonarParameters.SonarType`: HullMounted, Towed, VariableDepthSonar, DippingSonar (`SonarParameters.cs:16`); "activeintercept" = hull-mounted with `_isActiveIntercept` (`:112`). Bands LF/MF/HF = 1 / 3.5 / 30 kHz or explicit value (`:147`); optional separate active frequency.
- Fields: `_gain`, `_activeGain`, `_outputPower`, `_detectionTreshold` (ini `SNRDetectionThreshold`, default 5 dB), `_angularResolutionDegrees`, `_pseudorangeResolution`, `_signalProcessing`, `_maxConvergenceZones`, `_baffles`.
- Baffles: Vector2 degrees from the bow, default (120, −120), hull sonars only; check is private `Sonar.IsInBaffles` (`Sonar.cs:632`).
- **Ranges are cosmetic:** `_activeRangeInKm` / `_passiveRangeInKm` do not limit detection (they feed AI, UI, `GetRange`, `SensorSystemSonar.cs:98`); every object in the world is evaluated, no cut-off (`Sonar.cs:205`). **No ping interval:** active = `Sonar.IsActive` (ReactiveProperty, `:139`), re-evaluated each sensor tick.
- Listing: `unit._obp._sonarSystems`, `_activeSonarSystems` (`ObjectBaseParameters.cs:193-195`), `_towedSonarSystems` (towed, VDS, dipping; `SensorSystemSonar.cs:44-56`). Each `SensorSystemSonar` has `._sonar` (`Sonar`), `._sonar._sp`, `IsOn`, `Inoperable`, `CanProduceContacts`, `SensorPosition` (real mount/array position), `IsTowedSensor`, `IsVDS`, `_isDippingSonar`, `SearchBelowLayer`, `_parentTowedSystem.TowedSystemState` (`TowedSystem.cs:73`).
- Towed arrays sit 100 ft above or below the layer depending on `SearchBelowLayer` (`TowedSystem.cs:460-509`); cable length from ini `CableLength` (`ObjectBaseLoader.cs:1818`).
- Sonobuoys: `Bomb` objects with `_ap._subType == Ammunition.Type.Sonobuoy`, sonars in `WeaponBase._sensors` (`WeaponBase.cs:250`); `Deployed`, `RemainingLife` (`Bomb.cs:69,455`), `SonoDeployState` (Above/Below/Intermittent); depth = layer ± 30 ft (`Bomb.cs:179-238`); gated by `_transmitterRange`; they report to the taskforce plotting table, not to a unit (`Bomb.cs:511-513`).

## 2. Acoustic maths (all managed, public static)
- **Entry point:** `SonarContactMath.Evaluate(in SonarContactData) → SonarContactResult` (`SonarContactMath.cs:10`). Result: `SignalExcessDB`, `BearingRad` (atan2(z, x), not compass), `DistanceNM`, `PropagationLossDB`, convergence-zone / bottom-bounce / duct bonuses, `DirectShadowPenaltyDB`, per-source `SourceResults`. Seed the input with `SonarContactData.WithEnv(Globals._sonarEnvironmentParameters)` (`SonarContactData.cs:100`).
- Equations: passive SL − TL − NL + gain; active SL − 2TL + TS − NL + gain (`SonarAcoustics.cs:499-507`).
- `SonarAcoustics.cs`: `OwnNoiseDB` (`:72`; flow noise by speed, machinery, rafting, cavitation; towed/VDS −7 dB; dipping none), `BroadbandTargetSLDB` (`:106`), narrowband tonals `PropellerNarrowbandSL` (`:435`) / `MachineryNarrowbandSL` (`:476`), `BandAmbientNoise` (`:168`), `TransmissionLossDB` (`:286`; spherical to water depth, then cylindrical + bounce loss + `AbsorptionPerKmDB` `:280`), `AboveLayerLeakRatePerKmDB` (`:334`), `DuctBonusDB` (`:343`), `ConvergenceWindow` / `ConvergenceRingGainDB` (`:365-395`), `BottomBounceBonusDB` (`:397`), shadow zone (`:247-278`), reverberation (`:415-433`).
- Environment (`Environment.cs`): `getOceanNoise` (`:673`), `getSurfaceDuct` (`:716`), `getLayerHeight` (`:692`; thermal layer, see Topo's `LayerMap.cs`). **`getXLayerAttenuation` (`:754`) reseeds `UnityEngine.Random`** – call once and cache (the game uses the internal `SonarTickCache.XLayerAttenuation`).
- Tunables: `environment.ini [Sonar]` via `SonarEnvironmentParameters.cs:117-186`.
- How the game builds the input: `Sonar.ProcessPassiveContact` (`Sonar.cs:979-1152`) and `ProcessActiveContact` (`:1291-1338`) – both **private**, a mod copies ~80 lines. **Simplest recipe to copy: `SeapowerUI.ViewModels/SensorInfoViewModel.PlotSonar` (`:820-1001`)** – in a live mission it builds the input for one of the unit's sonars against a chosen target class and sweeps 251 ranges (read in this session: it uses `getOceanNoise(pos)`, depth from `TerrainUtils.GetHeightAt`, `getLayerHeight`, `getXLayerAttenuation`, `getSurfaceDuct`, `SonarAcoustics.OwnNoiseDB`, target `SimpleObjectParameters._sensorData._baseNoise`). Rotate `TargetPosition` around the sonar for a polar plot; bisect as in private `Sonar.GetDebugDetectionRangeNM` (`:1513`) for the detection range.
- Not reproducible from public state: narrowband integration over time (private `_nbIntegration`, `:109`, `:724-753`) and in-beam interference (`SonarContactMath.ApplyInterference`, `:184`) → mod range predictions will be slightly cautious.
- Ready-made estimate: `PointValueSensorScorer.EstimatePassiveSonarRangeNmi(sonarName, hostSensorData, speedKts, isSub)` (`:344`) – fixed reference environment, not position-aware.
- Model switch: `UseImprovedSonarModel` hard-coded true, `AswSimulation` Realistic (`OptionsManager.cs:448,520`); the old `SonarCalculator` now serves only torpedo seekers.

## 3. What a detection produces / how to read it
- Each detection = a track entity from `TrackComponent.MakeEmptyTrack` (`TrackComponent.cs:39`): `Epoch`, `MaxAge` (= 4 × DataLinkUpdateRate), `TrackBearing` = **true** compass bearing from the host plus an `Error` term (`Sonar.cs:363-370`; noise is only added later in the Burst TMA job `TMAUtils.cs:318`); passive only: `TrackRangeInMeters` (if the pseudorange setting is not NaN), randomized `TrackAltitude`, `ThresholdSignatureElement` classification bits (power plant, shafts, blades, electric frequency, distinctive noise; `:400-454`); `IncomingSignalData._incomingSignalValue` = signal excess dB (`:460`). Active tracks have exact range; torpedoes, noisemakers, decoys identified at once (`:562`, `:601-612`).
- Hooks, best first: (1) `sonar.Subscribe(IObserver<Entity>)` (`Sonar` is `IObservable<Entity>`, `:622/674`; the game wires it with `Subscribe(plottingTable)`, `ObjectBaseLoader.cs:2054`) – read components synchronously in `OnNext`; (2) poll after each tick: `sonar.RawPassiveSonarReadings` (`:141`) and `IntersectedEchoes` (`:143`) = `SensorEcho` lists with `_objectBase` (**ground-truth target – do not show**), `_signalValue` (SE), `_toTargetAngleRad`, `_distanceToSensorInM`, merged per beam; `_parentSonarSystem._detectedObjects`; (3) per fused contact: `Vehicle`'s `TrackBufferElement` buffer (`Vehicle.cs:885`).
- Track → sonar: `TrackComponent.Sensor` is the sensor's instance entity; its `SPSensor` component's `.Object` = the `SensorSystem` (`SensorSystem.cs:474`).

## 4. Existing sonar UI in the game
- **No waterfall anywhere.** Map bearing fans for passive sonar / ESM / active-intercept tracks exist (`Vehicle.cs:428-452`, `SeapowerUI/BearingFanViewModel.cs`) but are off unless `DM_Sensors._allowTMAFans = true` (`DM_Sensors.cs:63`); otherwise only the TMA ellipse.
- In-mission SE-vs-range plot: unit status "Sensor info" tab (`UnitStatusViewModel.cs:303`, `SensorInfoViewModel`).
- Main-menu modding tool `SonarTestViewModel.Plot` (`:1156-1393`): same sweep with hand-entered parameters; reads only `Globals._sonarEnvironmentParameters` and the `Environment` singleton, so its logic would run in a mission.
- F10 debug window `DM_Sensors.SonarSetupWindow` (`:1669`): `_debugSonar` fills `_debugPassiveSonarData` / `_debugActiveSonarData` with full breakdowns for **all** candidates (ground truth, not usable as player information). 3D debug layer lines: `DebugDrawShadowZone` (`:59-202`).

## 5. Torpedoes and countermeasures
Torpedo seekers use the old `SonarCalculator.GetPassiveSonarEcho/GetActiveSonarEcho` (`PassiveSonarSeeker.cs:97`, `ActiveSonarSeeker.cs:95`). Decoy success is a dice roll (`SeekerBase.CheckCountermeasureLock` `:400-525`, `_decoySpoofChance`, 35 s re-check). Readable: `_lockedOnTarget`, `_lockedOnCountermeasure`, `isActive()`, `_sensorEchoesInRange`. Noisemakers are `ObjectType.Noisemaker` (`Noisemaker.cs:315`) and appear as normal sonar contacts; active torpedoes/pinging units appear to passive sonars as an `ActiveEmission` source (`Sonar.cs:1657-1750`).

## 6. Threading and cost
Sonar model is managed, uses `Task.Run` + `Parallel.For` (`Sonar.cs:965`, `:1284`); results apply on the next tick (one tick lag, `CommitPassiveBatch` `:668`). Fusion and TMA: Burst ECS (`VehicleTMAUpdate`, `TrackSynthesizerUpdater`). Sonars run once per `DataLinkUpdateRate` (default 1 s), staggered (`SensorSystemsLink.cs:207-268`, `TaskforceManager.cs:61`).
`Evaluate` is pure struct maths with only `Mathf` calls → safe off the main thread; ~36k calls for 360° × 100 ranges → worker thread or spread across frames. Main-thread only: `TerrainUtils.GetHeightAt` and the `Environment` getters – sample them first.
